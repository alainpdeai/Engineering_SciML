2现场复现：让求解器「算出爆炸」

下面用最朴素的显式差分解一维热方程 u_t = u_xx，只改一个数——步长比 r = Δt/Δx²：

python · 显式差分：r 稍大就爆炸 可编辑 · Shift+Enter 运行
import numpy as np
import matplotlib.pyplot as plt

def explicit_heat(r, nx=41, nsteps=200):
    """显式差分解 u_t = u_xx；r = dt/dx^2，两端 u = 0"""
    x = np.linspace(0, 1, nx)
    u = np.sin(np.pi * x)
    peak = [np.abs(u).max()]
    for _ in range(nsteps):
        u[1:-1] = u[1:-1] + r * (u[2:] - 2 * u[1:-1] + u[:-2])
        peak.append(np.abs(u).max())
    return np.array(peak)

nsteps = 200            # r = 0.6 默认就爆炸；改成 4000 会溢出成 inf / nan
plt.figure(figsize=(6, 3.8))
for r in (0.4, 0.5, 0.6):
    peak = explicit_heat(r, nsteps=nsteps)
    print(f"r = {r}: 第 {nsteps} 步时 max|u| = {peak[-1]:.3e}")
    plt.semilogy(peak, label=f"r = {r}")
plt.axhline(1.0, color="gray", ls=":", lw=1)
plt.xlabel("time step")
plt.ylabel("max |u|")
plt.title("Explicit scheme: stable vs blow-up")
plt.legend()
plt.show()

r = 0.5: 第 200 步时 max|u| = 5.393e-01
r = 0.6: 第 200 步时 max|u| = 1.781e+12

▲ 运行结果：r=0.4/0.5 稳定衰减，r=0.6 指数放大到天文数字

你看到了什么：默认 nsteps = 200，三条曲线一起跑——r = 0.4 和 0.5 温度逐渐衰减，物理上合理；r = 0.6 只多了一点，数值却按指数放大，第 113 步越过 1，200 步约 1e12（把 nsteps 改成 4000 试试，会溢出成 inf / nan）——正是软件里的「NaN or Inf」。本地 Jupyter 里还会额外看到 overflow 警告，浏览器里只看得到 nan。
为什么光滑的 sin(πx) 初值也会爆炸？约 1e−16 的舍入误差会播种最高频模态；r = 0.6 时它每步被 |1 − 4r| = 1.4 倍放大。这里先建立直觉，完整的扩散稳定性推导在 M2.2。
现在让 Python 自己算崩。这是一个最朴素的显式差分，解一维热方程，只改一个参数 r。点运行：三条曲线一起出来，r 等于 0.4 和 0.5 时温度慢慢衰减，符合物理；r 等于 0.6，只多了一点点，数值却按指数放大，两百步就越过 1、量级到 1e12。把 nsteps 改成 4000 再运行，r 等于 0.6 的结果会变成 nan；在本地 Jupyter 里还会看到 overflow 警告，浏览器里没有这条警告，但数值同样是坏的。这就是软件里 NaN or Inf 的一种来源。原因我们在 M2 讲，这里只要记住：步长不是随便取的。首次点运行需要下载约 51 兆的 Python 运行时，页面打开几秒后其实已经在后台预加载了；请耐心等一会儿。

5拆解黑盒：商业软件的步骤，Python 里怎么写

同一件事有两条数值路径：本课程 M2 先手写有限差分（FDM），M3 再学有限元（FEM）。它们的矩阵不是一回事：

软件界面操作底层数学动作FDM 路径（M2，规则网格）FEM 路径（M3，任意几何）
1. 区域离散定义离散点 / 单元X, Y = np.meshgrid(x, y)三角形 / 四边形网格
2. 方程离散微分算子 → 代数关系main_diag = 4.0 * np.ones(N*N)（五点差分中心权重）弱形式 + 单元积分（虚功原理）
3. 装配全局矩阵得到 A（或 K）scipy.sparse.diags(...)：差分系数矩阵逐单元累加：刚度矩阵 K
4. 施加边界条件修改相应行与右端项边界行置 1、右端置边界值同一思想，对自由度处理
5. 求解与后处理解代数系统并画图u = spsolve(A, b)；plt.contourf(X, Y, u.reshape(N, N))同上（求解器不同）
要点：规则矩形网格上 FDM 又快又直观；换成 L 形域、带孔板、异形散热片，贴合边界就变得很痛苦——这正是引入 FEM 的动机（M3）。
商业软件的界面操作，大致可以拆成五步。看表：区域离散、方程离散、装配矩阵、施加边界、求解画图。Python 里对应的代码在第三列，那是有限差分路径；第四列是有限元路径。请注意，diags 生成的是差分系数矩阵，有限元的刚度矩阵是逐单元累加出来的，两者不是一回事，我们 M2 先做前者，M3 再做后者。

6现场体验：十来行代码画出二维温度场（解析解基准）

不用等课后，现在就画一张二维稳态导热云图：底边和两侧 0 °C，顶边按正弦加热。点 ▶ 运行，也可以先把 T0 改成 200 再运行：

python · 二维稳态导热（解析解） 可编辑 · Shift+Enter 运行
import numpy as np
import matplotlib.pyplot as plt

T0 = 100                                   # 顶边最高温度 (°C)，试试改成 200
x = np.linspace(0, 1, 50)
X, Y = np.meshgrid(x, x)
# 拉普拉斯方程的解析解：三边 0 °C，顶边按 T0·sin(πx) 加热
T = T0 * np.sin(np.pi * X) * np.sinh(np.pi * Y) / np.sinh(np.pi)

plt.figure(figsize=(5.5, 4))
plt.contourf(X, Y, T, levels=20, cmap="inferno")
plt.colorbar(label="Temperature (°C)")
plt.title("2D Steady Heat Conduction (analytical)")
plt.show()

▲ 运行结果：二维稳态导热解析解云图

注意：这不是数值解——它是把解析公式直接算出来。在 M2 里，你会手写差分矩阵去逼近这张图，并用它检验自己的求解器：解析解就是「标准答案」。

10新手必踩的 3 个暗坑：现象、原理、自救

坑 1 · 路径含中文或特殊字符
现象：UnicodeDecodeError，或脚本闪退。
原理：部分底层工具仍按系统本地编码处理路径，遇到非 ASCII 字符（尤其 Windows 用户名含中文时，用户目录本身就含中文）就解码失败。
自救：conda 安装目录与项目目录都放在纯英文路径，如 D:\Engineering_SciML\。
坑 2 · 虚拟环境混淆：装了包却找不到
现象：终端里 pip list 能看到包，Jupyter 里却 ModuleNotFoundError。
原理：Jupyter 运行代码的是内核（kernel），由 kernelspec 指向某个 Python 可执行文件；在终端 activate 只改变终端，不会改变已注册的内核。
自救：单元格里运行 import sys; print(sys.executable)，看路径是否来自 sciml_pde；不是就绑定内核（下一页）。
坑 3 · Matplotlib 云图中文变成方块
现象：标题「温度分布」显示成 □□□□。
原理：Matplotlib 按 font.sans-serif 列表依次找字体；找不到含汉字字形的字体，就用方块代替。
自救：设置带中文字体的回退列表（下一页）。另外，本页的浏览器 Python 没有中文字体，所以网页里的图一律用英文标签。
三个最常见的坑，每个都讲现象、原理、自救。第一，路径含中文，底层工具按本地编码解析路径，遇到中文就出错，所以路径全英文。第二，装了包却找不到：Jupyter 用的是内核，内核指向哪个 Python 是注册时决定的，你在终端激活环境并不会改变它，用 sys.executable 一查便知。第三，云图中文变方块，是字体回退列表里没有含汉字的字体。记住原理，比背解决方案更重要。

Lab实验台 2 · 改参数，看云图怎么变（M1）

拖动滑块，或直接编辑代码里的 T0、n、N，再运行。先点一次 ▶ 运行 加载运行时，之后拖动滑块会自动重画。

python · 单元格 2：参数化的温度场 可编辑 · Shift+Enter 运行
import numpy as np
import matplotlib.pyplot as plt

T0 = 100      # 顶边最高温度 (°C)
n = 2         # 顶边正弦的半波个数：1, 2, 3 ...
N = 60        # 每个方向的网格点数

x = np.linspace(0, 1, N)
X, Y = np.meshgrid(x, x)
T = T0 * np.sin(n * np.pi * X) * np.sinh(n * np.pi * Y) / np.sinh(n * np.pi)

plt.figure(figsize=(5.5, 4))
plt.contourf(X, Y, T, levels=20, cmap="inferno")
plt.colorbar(label="Temperature (°C)")
plt.title(f"n = {n}, T0 = {T0}")
plt.show()
print(f"最高温度 = {T.max():.1f} °C")
最高温度 = 100.0 °C

▲ 运行结果：参数化温度场（默认 n=2, T0=100）

最高温度 = 100.0 °C
观察题：n 增大时，高温区向板内渗透得更浅还是更深？改 N 会影响物理结果，还是只影响画面的精细度？（解析解与 N 无关；这一点在 M2 换成数值解后会变得不同。）
这是本讲最重要的一个实验，对应练习阶梯②：改参数，看结果。拖动 T0，颜色条的最大值随之变化；拖动 n，顶边的正弦波个数增加，热量渗入板内变浅；改 N，只改变画面的精细度，因为这是解析解，跟网格没有关系。到 M2 换成数值解，N 就会影响精度了。请你动手改，改的时候想一想：你预测的和看到的一致吗？

Lab实验台 3 · 向量化到底快多少？自己测

在网格节点上写原生 Python 循环，是科学计算里最常见的性能陷阱。别背数字，直接测：

python · 单元格 3：for 循环 vs NumPy 向量化 可编辑 · Shift+Enter 运行
import time
import numpy as np

N = 1_000_000
a = np.random.rand(N)
b = np.random.rand(N)

t0 = time.perf_counter()
s = 0.0
for i in range(N):                     # 纯 Python 循环
    s += a[i] * b[i]
t_loop = time.perf_counter() - t0

reps = 50                              # 向量化太快，重复多次取平均，避免计时精度不足
t0 = time.perf_counter()
for _ in range(reps):
    s_np = np.dot(a, b)                # NumPy 向量化
t_np = (time.perf_counter() - t0) / reps

print(f"for 循环 : {t_loop * 1000:9.1f} ms")
print(f"np.dot   : {t_np * 1000:9.3f} ms")
print(f"加速比   : {t_loop / t_np:9.0f} 倍（因机器而异，以你测到的为准）")
print(f"两种结果相差 {abs(s - s_np):.2e}（可能恰好为 0，也可能是极小的浮点误差：累加顺序不同）")
for 循环 :     408.4 ms
np.dot   :     0.774 ms
加速比   :       528 倍（因机器而异，以你测到的为准）
两种结果相差 0.00e+00（可能恰好为 0，也可能是极小的浮点误差：累加顺序不同）
思考：为什么 NumPy 快得多？（提示：循环在 C 里跑，且数据连续存放。）浏览器里的 Python 比本地慢，你在本地 Jupyter 里再测一次，比较两个加速比。
第三个实验，测一测向量化的加速比。左边是纯 Python 循环，对一百万个数做点积；右边是 np.dot。因为向量化太快，我重复五十次取平均，避免计时精度不足。加速比在不同电脑上不同，请以你测到的为准。浏览器里的 Python 比本地慢，你可以在本地 Jupyter 里再测一次做对比。
